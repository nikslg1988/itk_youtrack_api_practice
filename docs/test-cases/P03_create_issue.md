\# P03. Создание задачи

**Тип:** Позитивный

**Цель проверки:** Убедиться, что авторизованный пользователь может создать новую задачу в YouTrack через REST API, получить подтверждение её создания и проверить сохранение данных.

### Предусловия

1. YouTrack запущен и доступен.
2. Пользователь авторизован с помощью Permanent Token.
3. У пользователя есть разрешение Create Issue в целевом проекте.
4. Существует проект, в котором разрешено создание задач.
5. Известен внутренний ID целевого проекта.

### Параметры запроса

| Параметр | Значение |
|---|---|
| HTTP-метод | POST |
| Endpoint | `/api/issues` |
| Authorization | Bearer Token |
| Accept | `application/json` |
| Content-Type | `application/json` |
| fields | `id,idReadable,summary,description,project(id,name)` |

### Тестовые данные

| Поле | Значение |
|---|---|
| summary | Уникальное название, сформированное с помощью UUID |
| description | `Issue created using YouTrack REST API` |
| project.id | `0-0` |

**Пример тела запроса:**

```json
{
    "summary": "API automation test <UUID>",
    "description": "Issue created using YouTrack REST API",
    "project": {
        "id": "0-0"
    }
}
```

UUID генерируется отдельно при каждом запуске теста. Это обеспечивает уникальность тестовых задач при последовательном и параллельном выполнении.

### Шаги выполнения

1. Сгенерировать уникальное значение `summary` с помощью UUID.
2. Сформировать POST-запрос к endpoint `/api/issues`.
3. Передать токен авторизации в HTTP-заголовке Authorization.
4. Передать заголовок Accept со значением `application/json`.
5. Сформировать JSON-тело запроса с названием задачи, описанием и ID проекта.
6. Отправить запрос на сервер.
7. Проверить HTTP-статус и структуру JSON-ответа.
8. Проверить соответствие ответа Pydantic-модели `Issue`.
9. Проверить значения `summary`, `description` и `project`.
10. Извлечь внутренний ID созданной задачи из ответа.
11. Выполнить GET-запрос по полученному ID.
12. Проверить, что задача сохранилась и содержит переданные данные.
13. Удалить созданную задачу, используя внутренний ID.
14. Выполнить повторный GET-запрос и проверить отсутствие задачи.

### Ожидаемый результат

1. Сервер возвращает HTTP-статус `200 OK` при создании задачи.
2. Ответ имеет формат JSON.
3. Ответ содержит внутренний идентификатор созданной задачи (`id`).
4. Ответ содержит человекочитаемый идентификатор (`idReadable`).
5. Ответ содержит переданное название задачи (`summary`).
6. Ответ содержит переданное описание (`description`).
7. Ответ содержит объект проекта с корректными `id` и `name`.
8. Ответ соответствует Pydantic-модели `Issue`.
9. GET-запрос возвращает HTTP `200 OK` и подтверждает сохранение задачи с переданными данными.
10. DELETE-запрос успешно удаляет созданную задачу.
11. Повторный GET-запрос возвращает HTTP `404 Not Found`.

### Постусловия

Созданная тестовая задача удалена независимо от результата промежуточных проверок.

Исходные данные проекта не изменены.
