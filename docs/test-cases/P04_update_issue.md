# P04. Изменение названия существующей задачи

**Тип:** Позитивный

**Цель проверки:** Убедиться, что авторизованный пользователь может изменить название существующей задачи YouTrack через REST API и получить обновлённые данные.

### Предусловия

1. YouTrack запущен и доступен.
2. Пользователь авторизован с помощью Permanent Token.
3. У пользователя есть разрешение на изменение выбранной задачи.
4. В YouTrack существует задача, доступная пользователю.
5. Известен идентификатор задачи.

### Параметры запроса

| Параметр | Значение |
|---|---|
| HTTP-метод | POST |
| Endpoint | `/api/issues/{issueID}` |
| Authorization | Bearer Token |
| Accept | `application/json` |
| Content-Type | `application/json` |
| fields | `id,idReadable,summary` |
| Request Body | JSON с новым названием задачи |

**Тестовые данные**

| Параметр | Значение |
|---|---|
| issueID | Идентификатор существующей задачи |
| summary | API test: updated issue summary |

**Пример тела запроса:**

```json
{
    "summary": "API test: updated issue summary"
}
```

### Шаги выполнения

1. Выбрать существующую задачу и получить её текущие данные.
2. Сохранить исходное значение Summary.
3. Сформировать POST-запрос к endpoint `/api/issues/{issueID}`.
4. Передать токен авторизации в HTTP-заголовке Authorization.
5. Передать заголовки Accept и Content-Type со значением `application/json`.
6. Передать новое значение Summary в JSON-теле запроса.
7. Отправить запрос на сервер.
8. Получить и проверить HTTP-ответ.
9. Выполнить GET-запрос к той же задаче.
10. Проверить, что название задачи изменилось на переданное значение.

### Ожидаемый результат

1. Сервер возвращает HTTP-статус `200 OK`.
2. Ответ имеет формат JSON.
3. Ответ содержит идентификатор задачи (`id`).
4. Ответ содержит человекочитаемый идентификатор (`idReadable`).
5. Поле `summary` содержит новое название задачи.
6. Повторный GET-запрос возвращает задачу с обновлённым названием.
7. Остальные данные задачи не изменяются.
